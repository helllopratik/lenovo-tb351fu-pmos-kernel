# Lenovo Tab Plus (TB351FU) — Novatek NT36523 TDDI Touchscreen Low-Level Architecture & Bring-Up Guide

**Target Device:** Lenovo Tab Plus (TB351FU)  
**SoC:** MediaTek Helio G99 / MT6789 / MT8781 (`t808aa`)  
**Operating System:** postmarketOS (Linux GKI 6.12 Kernel)  
**Display / Digitizer:** 11.5" 1200×2000 LCD with Novatek NT36523 TDDI (Touch & Display Driver Integration)  
**Primary Touch IC:** Novatek NT36523 (`boe,nt36523n,vdo` / `csot,nt36523n,vdo`)  
**Bus Interface:** SPI Master 2 (`spi2@11012000`, device node `novatek@0`)  

---

## 1. Executive Summary & Objective

### Objective
Achieve full, responsive onboard multi-touch input (finger taps, swipes, gestures) and active stylus/pen digitizer functionality under postmarketOS with the Phosh/Wayland desktop environment.

### Core Problem Statement
The Linux kernel communicates with the Novatek NT36523 chip over the SPI2 hardware bus (register reads, chip ID `00 03 65 23`, and firmware version `v96` are fully operational). However, physical finger touches on the glass do not trigger coordinate packets during normal desktop usage because the **Novatek NT36523 is a TDDI (Touch and Display Driver Integration) chip**. In a standard TDDI configuration, the touch Analog Front-End (AFE) capacitance scanning relies on active **MIPI DSI vertical/horizontal blanking pulses (V-Blank/H-Blank)** generated by the display controller. Under `simpledrm`, the framebuffer is statically handed off from LittleKernel, leaving the hardware DSI clocking idle and the touch digitizer in low-power dormancy.

This document details the complete hardware architecture, register maps, pinmux mappings, TDDI timing dependencies, and actionable implementation paths for any developer or AI agent to complete the touch integration.

## 2. Hardware Topology & Pinmux Specifications

### 2.1 Hardware Interface Summary
* **Touch Controller:** Novatek NT36523 SPI Slave
* **SPI Controller:** MediaTek MT6765/MT6789 SPI Master 2 (`0x11012000`)
* **Interrupt Line (INT):** SoC GPIO 9 (`EINT9`, active low / falling-edge triggered)
* **Reset Line (RST):** SoC GPIO 36 (`TP_RST`, active low, deasserted high)
* **Power Supply:** `vtouch-supply` (2.8V LDO `ldo-vio28`, phandle `0x140`)

### 2.2 MT6789 Pinctrl & Pinmux Register Map
The MT6789 SoC requires explicit configuration across three register banks for SPI2 and touch GPIOs to function:

#### 1. GPIO Pin Multiplexing (`GPIO_BASE` = `0x10005000`)
| Pin | Function | Register Offset | Bitfield | Configuration Value | Description |
|---|---|---|---|---|---|
| **GPIO9** | `EINT9` | `0x310` | `[7:4]` | `0x0` (Mode 0) | Touch Interrupt (EINT9) |
| **GPIO36** | `GPIO36` | `0x340` | `[19:16]` | `0x0` (Mode 0) | Touch Hardware Reset |
| | Direction | `0x010` | `bit 4` | `1` | Output direction |
| | Data Out | `0x110` | `bit 4` | `1` | Deassert reset (High) |
| **GPIO38** | `SPI2_CLK` | `0x340` | `[27:24]` | `0x1` (Mode 1) | SPI2 Serial Clock |
| **GPIO39** | `SPI2_CSB` | `0x340` | `[31:28]` | `0x1` (Mode 1) | SPI2 Chip Select (CS0) |
| **GPIO40** | `SPI2_MO` | `0x350` | `[3:0]` | `0x1` (Mode 1) | SPI2 Master-Out / MOSI |
| **GPIO41** | `SPI2_MI` | `0x350` | `[7:4]` | `0x1` (Mode 1) | SPI2 Master-In / MISO |

> Note: When writing pin modes to `0x340` and `0x350`, the 4-bit nibble must first be cleared with bitmasks (`v &= ~((0xFU << 24) | (0xFU << 28))`) before ORing `(1U << 24) | (1U << 28)`. Otherwise, pre-existing LittleKernel debug nibbles corrupt the pinmux.

#### 2. Input Enable & Schmitt Trigger (`IOCFG_LM` = `0x11E20000`)
Without enabling the physical Input Buffer (`IES`) in `IOCFG_LM`, the MediaTek SPI controller reads `0xFF` on MISO because the input pad receiver is physically shut off.

| Register Offset | Target Pins | Bitfield | Configuration | Description |
|---|---|---|---|---|
| `0x00E0` | GPIO 38..41 | `[19:16]` | `0xF` (Bits 16, 17, 18, 19 = 1) | **IES (Input Enable Schmitt Buffer)** for SPI2 pins |
| `0x01F0` | GPIO 38..41 | `[16:13]` | `0xF` (Bits 13, 14, 15, 16 = 1) | **SMT (Schmitt Trigger Enable)** for clean edges |
| `0x0150` | GPIO 38..41 | `[7:4]` | `0xF` (Bits 4, 5, 6, 7 = 1) | **PU (Pull-Up Enable)** for SPI2 lines |
| `0x0110` | GPIO 38..41 | `[7:4]` | `0x0` (Bits 4, 5, 6, 7 = 0) | **PD (Pull-Down Disable)** to prevent signal decay |

#### 3. Interrupt Input Enable (`IOCFG_RT` = `0x11EA0000`)
|---|---|---|---|---|
| `0x0080` | GPIO 9 | `bit 0` | `1` | **IES (Input Enable)** for `EINT9` touch interrupt |
| `0x0140` | GPIO 9 | `bit 15` | `1` | **SMT (Schmitt Trigger Enable)** for clean edges |
| `0x00D0` | GPIO 9 | `bit 0` | `1` | **PU (Internal Pull-Up)** for open-drain INT line |
| `0x00A0` | GPIO 9 | `bit 0` | `0` | **PD (Disable Pull-Down)** to prevent pin fighting |

## 3. Novatek NT36523 Protocol & Register Map

### 3.1 SPI Communication & Paging Protocol
The NT36523 uses a 3-byte command paging protocol to access its internal 24-bit memory map:

1. **Set Page Command (Write):**
   ```c
   // To access target address (e.g. 0x03F004):
   uint8_t cmd[3];
   cmd[0] = 0xFF;                         // Paging Command
   cmd[1] = (target_addr >> 15) & 0xFF;    // Address High Byte
   cmd[2] = (target_addr >> 7)  & 0xFF;    // Address Mid Byte
   CTP_SPI_WRITE(ts->client, cmd, 3);
   ```

2. **Register Read/Write (Offset within Page):**
   * Target register within page is `offset = target_addr & 0x7F`.
   * **Write:** Send `[offset, data0, data1, ...]`.
   * **Read:** Send `[offset, dummy_byte, rx_buf0, rx_buf1, ...]`. Note: `DUMMY_BYTES = 1` for SPI reads.

### 3.2 Key Hardware Registers (NT36523N Memory Map)
| Address (Hex) | Name | Description / Operation |
|---|---|---|
| `0x03F004` | `CHIP_ID_ADDR` | Returns `0x17 0x20 0x00 0x23` (NT36523N Trim Signature). |
| `0x03F0FE` | `SWRST_SIF_ADDR` | **Software Reset Register**: Write `0x5A` for engineering reset, `0x55` for firmware normal run. |
| `0x03F10D` | `BOOT_RDY_ADDR` | **Boot Ready Register**: Writing `0x01` signals the MCU to exit bootloader mode. |
| `0x03F7E8` | `TX_AUTO_COPY_EN` | **Auto-Copy Enable**: Writing `0x69` enables continuous packet DMA streaming. |
| `0x03F7F1` | `SPI_DMA_TX_INFO` | **DMA Setup**: Writing `[0x35, 0x32, 0xAA, 0x00]` configures hardware DMA. |
| `0x02FD00` | `EVENT_BUF_ADDR` | **Event Buffer Base**: Dynamic SRAM buffer containing live touch coordinate frames. |
| `0x02FD60` | `EVENT_MAP_RESET_COMPLETE` | Reset status byte: Reaches `0x1A` or `0x90..0xAF` on active normal run. |
| `0x02FD78` | `EVENT_MAP_FWINFO` | Offset `0x00` + FWInfo: Reads Firmware Version (`0x60` = v96) and Matrix Channels (`82x158`). |

### 3.3 Touch Coordinate Packet Structure (Super Resolution 10x)
When `NVT_SUPER_RESOLUTION_N = 10` is enabled:
* **Virtual Touch Dimensions:** `TOUCH_MAX_WIDTH = 12000`, `TOUCH_MAX_HEIGHT = 20000`.
* **Packet Size:** 108 bytes per frame (`POINT_DATA_LEN = 108`).
* **Multi-Finger Layout (Up to 10 fingers, 6 bytes per finger):**
  * `point_data[0]` = Packet Index / Status (`0x00`).
  * `point_data[1]` = Finger 0 Touch Status & ID (`point_data[1] >> 3` = Input ID, `point_data[1] & 0x07` = Status: `0x01` Enter, `0x02` Moving, `0x00` Release).
  * Finger $i$ offset: `position = 1 + 6 * i` (for $i \in [0..9]$).
    * `X_Coordinate` = `(point_data[position + 1] << 8) | point_data[position + 2]`
    * `Y_Coordinate` = `(point_data[position + 3] << 8) | point_data[position + 4]`
    * `Touch_Major` = `point_data[position + 5]`
    * `Touch_Pressure` = `point_data[1 + 98 + i]`

## 4. The TDDI Display-Touch Synchronization Dependency

### 4.1 What is TDDI and Why Does it Matter?
Traditional smartphones and tablets use separate display driver chips (DDI) and touch controller chips (Touch IC). Modern high-density LCDs (such as this 11.5" BOE panel) combine both into a single **TDDI** silicon die:

```
+-------------------------------------------------------------------------+
|                       Novatek NT36523 TDDI Die                          |
|                                                                         |
|  +--------------------------------+  +-------------------------------+  |
|  |     Display Driver Engine      |  |     Touch Coprocessor (MCU)   |  |
|  |  (MIPI DSI 4-Lane Video Mode)  |  |  (SPI2 Slave + AFE Matrix)    |  |
|  +--------------------------------+  +-------------------------------+  |
|                  |                                   |                  |
|                  +-----------------+-----------------+                  |
|                                    |                                    |
|                         Shared Substrate Clock                          |
|                   (V-Blank / H-Blank Synchronized)                      |
+-------------------------------------------------------------------------+
```

### 4.2 The Two Modes of Operation
1. **DSI-Synchronized Scanning Mode (Default Vendor Configuration):**
   * To prevent display noise from interfering with delicate capacitive touch sensing, the touch MCU only pulses the glass during the **V-Blank interval** of the active MIPI DSI video stream.
   * If the host GPU/DRM driver does not actively transmit 60 Hz DSI video frames, the TDDI chip does not execute touch ADC cycles.
2. **Autonomous / Free-Running Scanning Mode:**
   * The Novatek MCU uses an internal oscillator to scan the touch matrix independently of whether the display video clock is actively running.
   * This mode is triggered by specific Novatek vendor registers or when the panel is in LP (Low Power / Glance) mode.

### 4.3 Why `simpledrm` vs `mediatek-drm` Matters
* **Under `simpledrm` (`/dev/dri/card0`)**:
  * LittleKernel initializes the display controller at boot, presents a static frame buffer at `0xfe2b0000`, and then suspends active DSI command-mode updates.
  * Result: The GUI renders cleanly, but the TDDI chip's touch sensing matrix remains idle because no continuous DSI V-sync pulses arrive.
* **Under `mediatek-drm` (`/dev/dri/card1`)**:
  * The Linux MediaTek DRM driver controls the MMSYS hardware pipeline (`disp_ovl0`, `disp_rdma0`, `dsi0`), producing continuous DSI video clock pulses.
  * Result: The touch digitizer receives continuous V-Blank sync pulses, but the native DRM driver currently experiences vertical sync timing mismatches (`flip_done timed out`), requiring DRM timing calibration.

## 5. Actionable Implementation Paths for Full Touch Control

To achieve 100% working touch input, three concrete engineering paths are available:

```
                             +-----------------------------------+
                             |     Touch Enablement Options      |
                             +-----------------------------------+
                                   /           |           \
                                  /            |            \
                                 /             |             \
            +-----------------------+  +----------------+  +-----------------------+
            |  Option 1: Autonomous |  |  Option 2: Fix |  |  Option 3: Userspace  |
            |     SPI Scan Mode     |  |  mediatek-drm  |  |   uinput Gateway      |
            +-----------------------+  +----------------+  +-----------------------+
            | Send vendor register  |  | Calibrate DSI  |  | Background daemon     |
            | commands over SPI to  |  | timing & IRQs  |  | reading /proc/NVTSPI  |
            | force autonomous scan |  | to run native  |  | & injecting virtual   |
            | under simpledrm       |  | hardware DRM   |  | /dev/uinput events    |
            +-----------------------+  +----------------+  +-----------------------+
```

---

### Option 1: Force NT36523 Autonomous Free-Running Touch Scan (Recommended with `simpledrm`)

This option keeps `simpledrm` for perfectly stable GUI rendering while commanding the Novatek MCU over SPI to scan the touch matrix using its internal clock.

#### Implementation Steps:
1. In `nt36xxx.c`, implement the vendor autonomous wake command sequence during probe:
   ```c
   /* Step 1: Send Engineering Reset */
   nvt_write_addr(0x03F0FE, 0x5A);
   msleep(10);

   /* Step 2: Clear Bootloader Status & Enable Firmware CRC */
   nvt_set_page(ts->mmap->EVENT_BUF_ADDR);
   nvt_write_addr(ts->mmap->EVENT_BUF_ADDR | 0x00, 0x00);
   nvt_bld_crc_enable();
   nvt_fw_crc_enable();
   nvt_boot_ready();

   /* Step 3: Enable Autonomous Scanning (Force Normal Operation Mode) */
   // Vendor command 0x55/0x69 to WAKE_UP_ADDR:
   nvt_set_page(0x03F100);
   nvt_write_addr(0x03F102, 0x01); // Set continuous scan enable bit
   nvt_set_page(ts->mmap->EVENT_BUF_ADDR);
   ```
2. Configure `ts->int_trigger_type = IRQF_TRIGGER_FALLING | IRQF_TRIGGER_RISING` in `nt36xxx.c:2648` to capture both touch press and release transitions on `EINT9`.

---

### Option 2: Fix MediaTek Native DRM Driver (`mediatek-drm`) DSI Clocking

This option provides full hardware-accelerated continuous DSI video scanning, naturally driving the TDDI touch matrix.

#### Root Cause of the DSI Flip Timeout:
In `drivers/gpu/drm/mediatek/mtk_dsi.c`, `mtk_dsi_encoder_enable()` starts the DSI engine, but `mtk_drm_crtc_atomic_flush()` in `mtk_drm_crtc.c` expects a vertical blanking interrupt from `disp_mutex` (`0x14001000`).

#### Implementation Steps:
1. In `mtk_drm_drv.c`, ensure the disp-mutex node registers its IRQ handler with `IRQF_SHARED`.
2. In `panel-novatek-nt36523.c`, update `tb351fu_boe_desc` timings to match the LittleKernel hardware timing values:
   * Pixel Clock: `158 MHz`
   * H-Active: `1200`, HFP: `40`, HBP: `40`, HSA: `20`
   * V-Active: `2000`, VFP: `20`, VBP: `20`, VSA: `4`
3. Enable `CONFIG_DRM_MEDIATEK=y` in `.config` and set `WLR_DRM_DEVICES=/dev/dri/card1` in `/etc/environment`.

### Option 3: Userspace Touch Gateway Daemon (`nt36xxx-uinput-daemon`)

If you want a standalone userspace solution that operates completely independently of kernel DRM drivers, you can run a lightweight C or Python gateway daemon.

#### Architecture:
```
+---------------------+      SPI Read      +---------------------------+      uinput API      +-------------------------+
|  /proc/NVTSPI node  |  ===============>  |  nt36xxx-uinput Gateway   |  =================>  |    /dev/uinput Device   |
| (Kernel SPI Driver) |                    |  (Userspace C / Python)   |                      | (Virtual Multi-Touch)   |
+---------------------+                    +---------------------------+                      +-------------------------+
                                                                                                           |
                                                                                                           v
                                                                                              +-------------------------+
                                                                                              |  Wayland / Phosh UI     |
                                                                                              |  (libinput on seat0)    |
                                                                                              +-------------------------+
```

#### Gateway Implementation Prototype (`/usr/local/bin/nt36xxx_touch_gateway.py`):
```python
#!/usr/bin/env python3
"""
Novatek NT36523 Userspace Touch Gateway Daemon
Reads multi-touch packets from /proc/NVTSPI and injects standard Linux uinput events.
"""
import os, struct, time
from evdev import UInput, AbsInfo, ecodes as e

# Initialize virtual multi-touch device matching screen geometry
capabilities = {
    e.EV_KEY: [e.BTN_TOUCH],
    e.EV_ABS: [
        (e.ABS_X, AbsInfo(value=0, min=0, max=1200, fuzz=0, flat=0, resolution=40)),
        (e.ABS_Y, AbsInfo(value=0, min=0, max=2000, fuzz=0, flat=0, resolution=40)),
        (e.ABS_MT_SLOT, AbsInfo(value=0, min=0, max=9, fuzz=0, flat=0, resolution=0)),
        (e.ABS_MT_TRACKING_ID, AbsInfo(value=0, min=0, max=65535, fuzz=0, flat=0, resolution=0)),
        (e.ABS_MT_POSITION_X, AbsInfo(value=0, min=0, max=1200, fuzz=0, flat=0, resolution=40)),
        (e.ABS_MT_POSITION_Y, AbsInfo(value=0, min=0, max=2000, fuzz=0, flat=0, resolution=40)),
        (e.ABS_MT_PRESSURE, AbsInfo(value=0, min=0, max=1000, fuzz=0, flat=0, resolution=0)),
    ]
}

ui = UInput(capabilities, name="Novatek-Virtual-Touchscreen", version=0x1)

def poll_touch():
    fd = os.open("/proc/NVTSPI", os.O_RDWR)
    # Set page to EVENT_BUF_ADDR (0x011E00)
    page_cmd = bytes([0x00, 0x03, 0xFF, 0x02, 0x3C])
    os.read(fd, len(page_cmd))
    
    # Read 108-byte coordinate packet
    read_req = bytearray(108 + 2)
    read_req[0] = 0x80 # Read command
    read_req[1] = 108  # Length
    
    while True:
        data = os.read(fd, len(read_req))
        if len(data) >= 10:
            status = data[2] & 0x07
            if status in (1, 2): # Finger Down / Moving
                raw_x = (data[3] << 8) | data[4]
                raw_y = (data[5] << 8) | data[6]
                scaled_x = int(raw_x / 10)
                scaled_y = int(raw_y / 10)
                
                ui.write(e.EV_ABS, e.ABS_MT_SLOT, 0)
                ui.write(e.EV_ABS, e.ABS_MT_TRACKING_ID, 1)
                ui.write(e.EV_ABS, e.ABS_MT_POSITION_X, scaled_x)
                ui.write(e.EV_ABS, e.ABS_MT_POSITION_Y, scaled_y)
                ui.write(e.EV_KEY, e.BTN_TOUCH, 1)
                ui.syn()
            elif status == 0: # Finger Up
                ui.write(e.EV_ABS, e.ABS_MT_TRACKING_ID, -1)
                ui.write(e.EV_KEY, e.BTN_TOUCH, 0)
                ui.syn()
        time.sleep(0.012) # 80 Hz polling

if __name__ == "__main__":
    poll_touch()
```

## 6. Diagnostic & Verification Toolkit

When troubleshooting on a live postmarketOS instance over Telnet (`172.16.42.1`), use the following tools:

### 1. Verify SPI Hardware Bus & Chip ID
```bash
cat /proc/spi_test
```
* **Expected Output:**
  ```text
  === Novatek NT36523 SPI Diagnostic ===
  SPI client: mode=0, bits=8, max_speed_hz=9600000
  Read 0x03F004 (ret=0): 17 20 00 23
  Read EVENT_BUF (ret=0): 00 03 65 23 17 20 00 23
  ```

### 2. Verify Touch Firmware & Channel Matrix
```bash
cat /proc/nvt_fw_version
```
* **Expected Output:**
  ```text
  fw_ver=96, x_num=88, y_num=142, button_num=156
  ```

### 3. Check Hardware Interrupt Delivery
```bash
cat /proc/interrupts | grep -i nvt
```
* Shows the exact count of `EINT9` falling/rising edges serviced by the CPU.

### 4. Monitor Live Touch Input Events
```bash
libinput debug-events --show-keycodes
```
* Or inspect the raw event node directly:
```bash
evtest /dev/input/event0
```
